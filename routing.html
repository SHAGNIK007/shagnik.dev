Understanding Routing

1. What is Routing?

Think of a web server as a massive office building, and routing is the friendly receptionist at the front desk.

When you (the client) walk in and ask for something (send a request), the receptionist needs to know two things: what you want to do (HTTP methods like GET for looking, or POST for delivering) and where you want to go (the URL path). The receptionist then maps your request to the right department (your server-side logic).

For JS users:
// Express.js Example
app.get('/users', (req, res) => {
    // Receptionist saying: "Ah, you want to SEE the users? Right this way!"
    res.json([{ name: 'Shagnik' }, { name: 'Soham' }]);
});
For Golang users (me btw):
// Golang Example
http.HandleFunc("GET /users", func(w http.ResponseWriter, r *http.Request) {
    // Receptionist saying: "Ah, you want to SEE the users? Right this way!"
    w.Header().Set("Content-Type", "application/json")
    w.Write([]byte(`[{"name": "Shagnik"}, {"name": "Soham"}]`))
})

2. Static Routes

Static routes are like dedicated rooms in a house that never move. For instance, the kitchen is always the kitchen. The URL path is fixed and unchanging.

If someone visits /api/books, they will always end up in the exact same spot, usually getting the exact same type of response.

For JS users:
// Static Route Example
app.get('/api/books', (req, res) => {
    res.send('Welcome to the library! Here are all the books.');
});
For Golang users (me btw):
// Static Route Example
http.HandleFunc("GET /api/books", func(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("Welcome to the library! Here are all the books."))
})

3. Dynamic Routes and Path Parameters

Imagine you're at a hotel. Instead of creating a unique route for every single guest (like /room-101, /room-102), we use a dynamic route.

We create a blueprint, like /rooms/:roomNumber. That parameter acts as a placeholder or a variable. When you visit /rooms/105, the server extracts "105" and knows exactly which room you're talking about.

For JS users:
// URL: /rooms/105
app.get('/rooms/:roomNumber', (req, res) => {
    const roomNumber = req.params.roomNumber; // e.g. "105"
    res.send(`Here are the details for room ${roomNumber}`);
});
For Golang users (me btw):
// URL: /rooms/105
http.HandleFunc("GET /rooms/{roomNumber}", func(w http.ResponseWriter, r *http.Request) {
    roomNumber := r.PathValue("roomNumber") // e.g. "105"
    w.Write([]byte("Here are the details for room " + roomNumber))
})

4. Query Parameters

If path parameters are for finding a specific thing, query parameters are for filtering or customizing what you found.

Think of it like ordering coffee. The path is /coffee. But maybe you want it iced, with oat milk, and a pump of vanilla. You append those details to the end of your request using a question mark ?.

In the URL, it looks like /coffee?size=large&milk=oat. Since GET requests can't carry heavy packages (request bodies), query parameters are the perfect way to pass along these extra instructions.

For JS users:
// URL: /coffee?size=large&milk=oat
app.get('/coffee', (req, res) => {
    const size = req.query.size; // "large"
    const milk = req.query.milk; // "oat"
    res.send(`Preparing a ${size} coffee with ${milk} milk.`);
});
For Golang users (me btw):
// URL: /coffee?size=large&milk=oat
http.HandleFunc("GET /coffee", func(w http.ResponseWriter, r *http.Request) {
    size := r.URL.Query().Get("size") // "large"
    milk := r.URL.Query().Get("milk") // "oat"
    w.Write([]byte("Preparing a " + size + " coffee with " + milk + " milk."))
})

5. Nested Routes

Nested routes are for when relationships get a bit complicated. Imagine you're trying to find a specific page inside a specific book that belongs to a specific library.

A nested route looks like this: /api/users/123/posts/456.

It reads exactly like a sentence: "Go to the user with ID 123, look at their posts, and grab the post with ID 456." It organizes your data cleanly by wrapping relationships directly into the URL.

For JS users:
// Nested Route Example
app.get('/api/users/:userId/posts/:postId', (req, res) => {
    const { userId, postId } = req.params;
    res.send(`Grabbing post ${postId} written by user ${userId}`);
});
For Golang users (me btw):
// Nested Route Example
http.HandleFunc("GET /api/users/{userId}/posts/{postId}", func(w http.ResponseWriter, r *http.Request) {
    userId := r.PathValue("userId")
    postId := r.PathValue("postId")
    w.Write([]byte("Grabbing post " + postId + " written by user " + userId))
})

6. Route Versioning and Deprecation

Imagine your favorite restaurant suddenly changes its entire menu overnight. Chaos, right? That's what happens if you change an API without versioning it.

Versioning is like having two menus. You put v1 in the URL for the old menu, and v2 for the new one (e.g., /api/v1/products vs /api/v2/products).

This gives developers time to switch their apps over to the new menu without their existing apps crashing. Once everyone has moved over, you can finally throw the old menu away.

For JS users:
// Versioning Example
app.get('/api/v1/products', (req, res) => {
    res.json({ id: 1, title: 'Old format' });
});

app.get('/api/v2/products', (req, res) => {
    // The new format
    res.json({ productId: 1, productName: 'New format' });
});
For Golang users (me btw):
// Versioning Example
http.HandleFunc("GET /api/v1/products", func(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    w.Write([]byte(`{"id": 1, "title": "Old format"}`))
})

http.HandleFunc("GET /api/v2/products", func(w http.ResponseWriter, r *http.Request) {
    // The new format
    w.Header().Set("Content-Type", "application/json")
    w.Write([]byte(`{"productId": 1, "productName": "New format"}`))
})

7. Catch-All Routes

Sometimes, someone asks the receptionist for a department that doesn't exist. Instead of just staring at them blankly (which is what a server normally does), we use a catch-all route.

It’s the "Lost and Found" of your website. Represented by a wildcard like /*, it catches any request that didn't match a real route and politely tells the user, "Oops, you're lost!"

For JS users:
// Catch-All Route Example
app.get('*', (req, res) => {
    res.status(404).send('Error 404: Whoops! This page doesn\'t exist.');
});
For Golang users (me btw):
// Catch-All Route Example
http.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
    // The "/" path catches anything that doesn't have a specific handler
    w.WriteHeader(http.StatusNotFound)
    w.Write([]byte("Error 404: Whoops! This page doesn't exist."))
})
